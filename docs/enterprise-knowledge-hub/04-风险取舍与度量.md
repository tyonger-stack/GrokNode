# 04 · 性能 / 成本 / 一致性：风险、取舍与度量体系

> **本章结论**：本方案的主要风险**不在吞吐，而在三类"看不见的慢"**——权限撤销的传播延迟、记忆抽取的静默成本、以及"过滤发生在召回之后"这类正确性缺陷被性能表象掩盖；因此度量体系必须把**正确性指标（过滤是否真下推、撤权是否真生效）与性能指标同等对待**，并为每个阶段设置**明确的退出点**。

---

## 4.1 性能风险与取舍

| # | 风险描述 | 量化影响 | 取舍 | 缓解措施 |
| --- | --- | --- | --- | --- |
| P1 | **权限过滤未真正下推到索引**（退化为召回后裁剪） | 官方口径：标量过滤 + 向量检索相比先检索再过滤**性能提升 3 倍以上** [B]；正确性上 top-k 被权限吃掉，**有效召回率可跌至目标值的 20–30%** | **必须下推**（不做 A/B 长期并行） | ① `pre_filter_candidates` vs `post_filter` 写入 trace 并设断言；② 契约测试强制 `acl_bucket` 索引存在；③ 集合按安全域物理隔离作为兜底 |
| P2 | **桶化反范式导致 top-k 被同 chunk 的多行占位** | 桶数 N=5 时，top-k=50 实际只得到 ~10 个不同 chunk，**有效召回率降至 20%** | 接受存储放大，换取确定性的过滤语义 | top-k **预放大**（`top_k = k × 平均桶数 × 1.5`）+ 归并去重；把"有效不同 chunk 数"写入 trace 并告警 |
| P3 | **存储放大 N 倍**（N = 桶数） | 向量存储 ×N；若 N=8，1000 万 chunk 的向量存储从 ~40GB 涨到 ~320GB（1024 维 float32） | 优先用**粗桶**（域/部门），个人级桶例外审批 | ① 桶粒度策略表；② 存储成本纳入度量，超阈值触发桶合并；③ 向量量化/降维（需重测召回） |
| P4 | **VikingDB 向量索引更新延迟约 20 秒** [B] | 新写内容最长 20 秒不可检索；撤权同样有 20 秒窗口 | **接受**（可接受"看不到新内容"），**不接受**（不接受"看到已撤内容"） | 写侧：写入后标记 `pending_index`，未就绪前不返回；撤权侧：overlay 兜底（5s） |
| P5 | **OpenViking 每次 commit 调 LLM 做摘要/抽取/去重** [A/B] | 高频短会话场景下抽取成本不可忽略；单次抽取成本 ≈ 1 次 LLM 调用 + 上下文 | 接受"不是每轮都抽" | 分级触发（§2.3.a.1）+ 增量抽取 + 小模型初筛 + 每主体每日抽取预算熔断 |
| P6 | **双阶段检索（意图分析 + 层级检索 + Rerank）增加延迟** | 官方口径查询延迟降低 58–66% [D 厂商数据]，但那是相对基线；绝对值仍需自测 | 接受（用质量换延迟） | 简单 query 走 `find()` 跳过意图分析（OpenViking 官方支持该区分 [A]）；Rerank 只对 top-50 做 |
| P7 | **集合数随部门增长** | 100 部门 ⇒ 100 次查询或需要跨集合融合 | 接受（物理隔离的安全收益 > 查询开销） | 按安全域而非部门切集合（合并同安全域的部门）；跨集合融合用"并发查 + 应用层归并" |
| P8 | **多 Agent 同会话时 G0 互相污染** | 一个 Agent 的错误推断被另一个当事实 ⇒ 错误放大 | 接受（协作必要） | G0 条目强制 `author_agent` 标注；"推断"类条目加"待确认"标记；装配时对跨 Agent 的推断降权 |

## 4.2 成本风险与取舍

| # | 风险描述 | 量化影响 | 取舍 | 缓解措施 |
| --- | --- | --- | --- | --- |
| C1 | **Embedding 成本**（全量 + 增量） | 1 亿 chunk × 1024 维，单次全量重建成本可观 | 接受（可重建性换取正确性） | 增量重嵌入（按 `doc_version` 变化范围）；模型版本固定，不随意换模型；抽样重建校验（契约 T4） |
| C2 | **抽取 LLM 成本** | 每会话 1 次抽取 + ≤2 次分类 | 接受，但**必须熔断** | 每主体每日抽取次数上限；质量分低于阈值的会话不抽；批量/夜间跑 |
| C3 | **Rerank 成本与延迟** | top-50 重排，单次 ~40ms（自测值） | 接受 | 只对 top-50 重排；低价值 query 跳过重排；缓存相同 query 的重排结果（按主体分区缓存，防跨主体泄漏） |
| C4 | **存储成本单调增长**（归档层不删） | 按 10⁷ chunk、保留 3 年估算，量级需实测 | 接受（保护资产） | 冷热分层 + 生命周期（归档层转对象存储）；墓碑只留元数据；**季度成本复核触发保护名单收缩** |
| C5 | **多系统重复建设**（每个 AI 系统各接各的） | N 个系统 ⇒ N 套胶水、权限实现分叉 | **必须消除** | 中台提供统一 MCP/REST 出口；系统只做"业务编排"，不做知识存取 |
| C6 | **VikingDB 托管成本随规模非线性上升** | 单分片 ≤ 2000 万条 768 维 [B]；分片数 = 总量/单分片承载 + 25% 冗余 [B] | 接受（免运维的价值） | 规模规划前置；用聚合统计做用量分析（官方已支持 sum/avg/min/max、group_by、vector_weighted_sum [B]） |
| C7 | **治理人力成本被低估** | 仲裁队列、域评审、晋升审批、影响巡检都是**人** | **这是最大的隐性成本** | ① 指标反哺降低人工量（MHR/CAR）；② P0/P1 阶段**限定 1–2 个域**；③ 治理角色兼职化但**职责显式**；④ 把"治理工时"列入预算 |
| C8 | **OpenViking 商业托管费用** | 记忆数据出域 + 按量计费 | 自建（路径 B） | 见 §3.4；自建的真实成本是**运维人力**，须计入 TCO |

> **C7 值得单独强调**：本方案的失败模式**大概率不是技术失败，而是治理失败**——仲裁队列积压、域评审流于形式、晋升通道无人执行，最终 G2 变成"没人维护的旧仓库"。**阶段化退出点（§4.5）就是为此设计的。**

## 4.3 一致性风险与取舍

| # | 风险描述 | 量化影响 | 取舍 | 缓解措施 |
| --- | --- | --- | --- | --- |
| S1 | **三副本漂移**（WeKnora 正文 / VikingDB 向量 / OpenViking 记忆） | 文档更新后 5–30 分钟内出现"Wiki 已改、向量未改" | 接受最终一致 | 每日一致性巡检（§4.4 流程）；`doc_version` + `source_hash` 双校验；漂移即重嵌入 + 旧行 overlay deny |
| S2 | **权限撤销传播不一致**（Grant 表已改，overlay 未生效） | 最长 20 秒越权窗口 [B] | **不接受** | ① overlay 优先于索引；② Redis + 本地双级缓存；③ **fail-closed**（缓存不可用时拒绝敏感检索）；④ 撤权事件带版本号，乱序时取更高版本 |
| S3 | **抽取异步导致的"记忆晚到"** | 结论在会话结束后延迟 1–5 分钟才沉淀 | 接受 | 关键结论走**显式提交**通道（≤30s）；会话内不依赖未沉淀的记忆 |
| S4 | **冲突判定漏检**（断言键抽取失败 ⇒ 判不出矛盾） | 错误记忆静默共存，污染 G2 | 接受（无法归零） | ① 断言键抽取失败 ⇒ 降级为"按相似度提示疑似冲突"；② 抽样人工复核；③ 监控"未解析断言键比例"指标 |
| S5 | **记忆→知识晋升后，原记忆仍活跃** | 同一结论两个版本并存，且知识版本可能过时 | 接受（保留历史） | 晋升时**自动**把源记忆标 `SUPERSEDED`（可回滚），但**不删除** |
| S6 | **知识变更后，引用它的记忆不会自动失效** | OpenViking 官方明确：级联更新是**开放难题** [A/B] | **必须自建** | 血缘链 + 每日"知识变更影响巡检"→ 引用记忆进复核队列（**人工/规则确认，不自动改写**） |
| S7 | **共享区副本与源不一致** | 副本是快照，源可能已变 | 接受（副本语义即冻结） | 副本带 `source_ref` + `source_version`；源变更触发 24h 复核队列（高敏 1h）；一键下架 |
| S8 | **多系统写入同一 G2 域** | 写冲突、结论不可复现 | 接受 | 关键记忆按 `assertion_key` **串行化队列**（§2.4.4）；幂等键 |
| S9 | **重试导致重复抽取** | 记忆条目膨胀、命中率下降 | 接受 | 幂等键 = `hash(session + message_range + model_version)` |
| S10 | **deny-overlay 缓存过期后"复活"** | 已撤销的访问在 60s 后重新可用 | 接受（overlay 是加速器，权威在 Grant 表） | 定时对账：每 5 分钟比对 Grant 表与 overlay，发现缺失即补推；**对账失败即告警** |
| S11 | **治理元数据只存在 AGFS 里（A15）** | 仲裁记录、冲突队列、评审决策**不可再生**（它们是"当时的判断"，原文无法重建）；若随记忆库一起损坏 ⇒ 治理历史永久丢失 | **不可接受** | 治理元数据**独立存储**（关系库 + 定期快照），**不作为唯一副本放在 AGFS**；每季度做一次"AGFS 全损 ⇒ 治理历史可恢复"的演练 |
| S12 | **记忆库成为单点（A14/A17）** | OpenViking 停服/损坏 ⇒ 所有专业系统同时"失忆"，且**不报错、只是变差**（最难察觉的故障） | 接受（集中带来的收益更大），但**必须可降级** | ① 知识权威副本始终在 WeKnora ⇒ 记忆库全灭**知识资产不受损**；② **降级路径 P0 必做**（无记忆模式）；③ **季度"记忆库不可用演练"** |

## 4.4 度量体系

**结论**：度量分三层——**正确性层（最高优先级）、性能层、成本层**；正确性指标未达标时，性能优化无意义。

### 4.4.1 正确性层（安全与语义正确）

| 指标 | 定义 | 目标值 | 反哺动作 |
| --- | --- | --- | --- |
| **过滤下推率 FPR** | `post_filter_candidates ≥ top_k` 的检索占比 | **≥ 99%** | < 95% ⇒ 停用该路径并排查索引配置 |
| **有效召回率 ERR** | 去重后不同 chunk 数 / 目标条数 | **≥ 85%** | 偏低 ⇒ 调 top-k 放大系数、合并桶 |
| **撤权传播延迟 RCL** | 撤销事件 → overlay 生效的 P99 | **≤ 5 秒** | 超标 ⇒ 检查事件总线与缓存刷新；必要时 fail-closed |
| **越权召回数** | 红队/审计发现的越权返回条数 | **= 0** | 任何非零 ⇒ **P0 事件**，立即停用相关路径 |
| **黑盒探针失配数（A9）** | 独立探针服务用随机 principal 对随机 chunk 检索，"应可见集合"与"实可见集合"的差集大小 | **= 0** | 非零 ⇒ 裁决或过滤下推有实现缺陷，**立即 P0** |
| **ACL 集合完备性（A9）** | 用**独立的第二个实现**复算同一主体的应得桶集合，与裁决输出比对的一致率 | **100%** | < 100% ⇒ 两个实现有分歧，定位到具体桶类型 |
| **红队流量覆盖率（A9）** | 被测 principal 组合数 / 应测组合数 | **≥ 90%** | 覆盖率不足 ⇒ "越权数 = 0"这个指标**没有意义**，不得据此结案 |
| **断言键解析率 AKR** | 成功抽取断言键的候选占比 | **≥ 90%** | 偏低 ⇒ 改进抽取 schema/模型；未解析的走相似度疑似冲突通道 |
| **冲突漏检率** | 人工抽检发现的未标记冲突占比 | **≤ 3%** | 超标 ⇒ 调关系分类阈值 |
| **副本一致率** | 共享区副本的 `source_version` 与源当前版本一致的占比 | **≥ 95%** | 偏低 ⇒ 缩短复核 SLA；**不自动同步**（快照语义） |
| **血缘完整率** | 有有效 `source_refs` 的记忆占比 | **≥ 95%** | 偏低 ⇒ 无引用记忆降权注入 |

### 4.4.2 性能层

| 指标 | 定义 | 目标值 | 反哺动作 |
| --- | --- | --- | --- |
| 检索 P50 / P99 | 端到端（裁决 + 召回 + 重排 + 装配） | P50 ≤ 120ms / P99 ≤ 400ms | 超标 ⇒ 分段拆解定位（trace 已有分段耗时） |
| 裁决延迟 | Permission Service 单次 authorize | P99 ≤ 20ms | 授权缓存命中率 < 80% ⇒ 查 EPS 展开成本 |
| 重排延迟 | top-50 重排 | P99 ≤ 80ms | 降 top-k 或换轻模型 |
| 装配延迟 | token 装箱 + 掩码 + 纯度校验 | P99 ≤ 30ms | 纯度校验 O(n²) 嫌疑 ⇒ 预计算 |
| 撤权可见性 | 撤销到检索不再返回 | **P99 ≤ 5s** | 与 RCL 同源 |
| 抽取延迟 | 触发到候选入池 | P99 ≤ 5 分钟 | 超标 ⇒ 检查队列积压 |

### 4.4.3 成本层

| 指标 | 定义 | 目标值 | 反哺动作 |
| --- | --- | --- | --- |
| 抽取 LLM 成本 / 会话 | 折算 token 或金额 | ≤ 基线预算 | 超标 ⇒ 收紧触发条件、提高质量分阈值 |
| Embedding 成本 / 增量批次 | 重嵌入成本 | ≤ 预算 | 超标 ⇒ 减少重嵌入范围（按受影响 chunk 而非整文档） |
| 单次问答的检索侧成本 | Rerank + 检索 + 装配的边际成本 | 跟踪趋势 | 趋势恶化 ⇒ 检查 top-k 与桶数 |
| 存储成本 / 有效 chunk | 含放大系数 | 跟踪趋势 | 超标 ⇒ 桶合并 + 冷存储分层 |
| 治理工时 / 域 / 月 | 仲裁 + 评审 + 晋升审批 | **必须预算** | 超标 ⇒ 缩小域范围（P0/P1 限定 1–2 域） |
| **治理工时 / 有效共享记忆数** | 单位产出的人工投入 | 趋势下降 | 不下降 ⇒ 自动化不足或域过多 |

### 4.4.4 记忆质量层（承第 2 章）

| 指标 | 目标值 | 关联动作 |
| --- | --- | --- |
| 记忆命中率 MHR | ≥ 40% | 调注入门槛 |
| 冲突自动仲裁率 CAR | ≥ 70% | 调分差阈值 τ |
| 淘汰准确率 EAR | ≥ 95% | 调 TTL / 保护名单 |
| 回滚频次 RRF | ≤ 5‰ | 收紧抽取门槛 |
| 记忆污染率 MPR | **≤ 2%（硬上限）** | 提高时间新鲜度权重、暂停冲突条目注入 |
| 长期分歧数 LDC | 每域 ≤ 20 | 升级人工仲裁 SLA |
| G3 规模 | ≤ 10⁴ | 触发存量评审 |

### 4.4.5 组织健康度层（A10）

**结论**：技术指标全绿**不代表系统健康**——三年后的典型退化是"没人维护、没人认领、权限漂移"，而这些**在任何技术指标上都看不见**；因此必须有一组**专门度量组织性退化**的指标。

| 指标 | 定义 | 目标值 | 反哺动作 |
| --- | --- | --- | --- |
| **孤儿 ACL 桶率** | ACL 中 `user:` 桶对应主体已失效（离职/停用）的比例 | **≤ 1%** | 超标 ⇒ 生成清理任务（**不自动删**，因为可能有审计价值，但要有人处理） |
| **无主记忆率** | G2 中 90 天零访问且无 owner 的条目占比 | **≤ 10%** | 超标 ⇒ 触发"无人认领回流"，向域负责人推送待办 |
| **关键角色覆盖率** | 有在岗**域主 + 备份**双岗的域数 / 总域数 | **100%** | 缺备份 ⇒ 该域 **G2 写入冻结**（见 §4.5） |
| **G3 无人触碰率** | G3 连续 12 个月未被复核的条目占比 | **0%** | 非零 ⇒ 冻结 G3 写入，启动全量审计 |
| **单条记忆影响面** | 单条记忆被 ≥ 3 个系统引用的条目数 | 趋势监控 | 突增 ⇒ 触发红队复核（**错误传播速度**，见 05 章 Q15） |
| **知识 stale 率** | `knowledge_freshness` 为 `stale`/`disputed` 的知识占比 | **≤ 5%** | 超标 ⇒ 触发复核（**知识腐化**，见 05 章 Q4） |

> **这组指标的意义**：它们度量的是**组织能力**而不是系统状态。它们的恶化往往**先于**技术故障出现——仲裁队列积压、域主空缺、孤儿桶堆积，都是"这套系统正在变成没人维护的旧仓库"的早期信号。

### 4.4.6 仪表盘分层与告警

| 视图 | 面向 | 关键卡片 |
| --- | --- | --- |
| **安全看板** | 安全 / 合规（每日） | 越权召回数、撤权延迟、ACL 漂移数、墓碑合规、差异攻击告警 |
| **质量看板** | 领域专家 / 治理官（每周） | MHR、CAR、EAR、RRF、MPR、长期分歧、晋升率、**无主记忆率** |
| **组织健康看板（A10）** | 负责人 / HR（每月） | 孤儿 ACL 桶率、关键角色覆盖率、G3 无人触碰率、治理工时趋势 |
| **性能看板** | 运维（实时） | 各段延迟、过滤下推率、有效召回率、队列积压 |
| **成本看板** | 财务 / 负责人（月） | 抽取/嵌入/重排/存储成本、治理工时 |

**红线（触发即升级为 P0，不等周期）**

| # | 红线 | 动作 |
| --- | --- | --- |
| R-1 | 越权召回数 > 0 | 立即禁用相关检索路径、切 fail-closed、启动事件响应 |
| R-2 | 记忆污染率 > 2% 连续 3 天 | 暂停 G2 记忆注入，全量复核 |
| R-3 | 撤权延迟 P99 > 30s | 切保守模式（拒绝敏感域检索） |
| R-4 | G3 出现一条无审核记录 | 冻结 G3 写入，启动全量审计 |
| R-5 | 墓碑被检出含内容残留 | 立即清除 + 合规上报 |

## 4.5 阶段化路线与退出点

**结论**：**每个阶段都必须是"可以停在这里"的完整系统**；任何阶段未达成判据就进入下一阶段，是本方案最主要的失败模式。

| 阶段 | 范围 | 交付 | **退出点（判据）** | 失败时的动作 |
| --- | --- | --- | --- | --- |
| **P0 概念验证**<br>4–6 周 | **1 个 AI 系统 + 1 个部门**；WeKnora 做分片/VikingDB 做检索；权限**只用「部门 + 岗位」两层**；**不做 G2/G3**；无自动化治理 | 统一 Chunk Schema、写入流、检索流、基础装配、trace、**无记忆降级路径（A14）** | ① 该域知识命中率相对基线提升 **≥ 20%**（同 query 对比）；② 端到端 P99 ≤ 400ms；③ 团队愿意继续投入；④ **断开记忆库后系统可降级运行而非崩溃**（A14） | **缩小范围再试一次**；仍不达标 ⇒ 判定"该域无共享价值"，**不要进入 P1** |
| **P1 四层权限 + G1**<br>8–10 周 | Permission Service 上线；四层主体 + 矩阵/外部；召回期 overlay；G1 个体记忆闭环；红队用例库 | 权限主干 + 个体记忆 + 审计 + **用户可见的记忆面板**（知情同意载体） | ① 撤权延迟 P99 ≤ 5s；② 红队越权用例 **0 通过**；③ 记忆污染率 ≤ 2%；④ **制度门禁全部就位（A17）** | 优先修权限主干，**G1 可延后**；权限不达标不进 P2 |
| **P2 G2 领域记忆**<br>8–10 周 | 跨系统共享记忆；断言键 + 仲裁；双记并查 + 人工队列；固化/泛化；**语境契约 + 本体对齐**；指标反哺 | 领域记忆 + 仲裁闭环 | ① 冲突自动仲裁率 ≥ 70%；② 至少完成 **1 次真实的人工仲裁**并据此改进规则；③ 至少 1 个域完成 **1 次"记忆→知识"治理晋升**；④ **域主 + 备份双岗到位（A11）** | 若人工仲裁队列积压 > 100 且无人处理 ⇒ **说明治理投入不足，回 P1 补人力**；**无备份的域禁止进入 G2 写入** |
| **P3 G3 + 回流闭环**<br>持续 | 治理委员会机制；知识回流三线（来源变化 / 工作成果 / 使用反馈）；年度评审；常态化红队 | 组织级记忆 + 全链路闭环 | ① G3 错误率 < 1%；② 知识回流三线**每条都有实际发生记录**（不是纸面设计）；③ 具备**单域下线能力** | — |
| **P4（可选）规模化** | 多域、跨域订阅、跨组织外部协作 | 外部协作方、订阅市场 | 独立法务意见（AGPL + 外部数据） | — |

**"单域下线能力"的判定（必须真做一次）**

> 任选一个域，执行"取消该域的所有共享授权 → 观察该域的 G2 记忆、共享区副本、向量 ACL 行是否全部收敛"，
> 并验证：**该域内容在 5 分钟内从所有检索路径消失，且无残留副本可被检索到。**
> **没做过这个演练 ⇒ 不具备下线能力 ⇒ 不进入 P3。**

**P1 制度门禁清单（A17：缺一项则不进入 P2）**

> 这套系统会**隐性地要求**组织做出制度选择。回避这些要求的方案，最终会因"制度没跟上"而失败——而失败原因常被误判为"技术不行"。因此把它们做成**门禁**而非建议。

| # | 门禁项 | 判定标准 |
| --- | --- | --- |
| G1 | **域主名单已确定（主 + 备份）** | 每个域 ≥ 1 名在岗域主 + 1 名备份；缺备份 ⇒ **该域 G2 写入冻结**（A11） |
| G2 | **知情同意文案已发布** | 用户可查看"系统记住了我的什么"；含用途、保存期限、删除方式 |
| G3 | **用户可见的记忆面板已上线** | 用户可看/改/删自己的 G1（这是知情同意的技术载体，也是最便宜的数据质量提升手段） |
| G4 | **被遗忘权流程已可执行** | 有受理入口 + 责任人 + 时限 + 9 类派生面处理清单（§2.3.d.4） |
| G5 | **治理委员会章程已通过** | 明确成员、否决权、G3 发布流程、回避规则 |
| G6 | **审核工时有预算** | 每个域每周 ≥ 4h 的审核/仲裁工时已排入日程 |
| G7 | **HRIS 已打通** | 聘任/离职/调岗事件能进入权限链路；**含外包与临时授权** |
| G8 | **"默认不共享"已在组织内沟通** | 明确告知"这套系统的默认姿态与'信息默认流通'的直觉相反，这是刻意的"，并给出例外流程 |

> **为什么 G8 特别重要**：若组织文化默认信息流通，人们会**绕过系统**继续用邮件和 IM——**那时系统收集到的，恰恰是最不该收的那部分**（未审核、含个人信息、无血缘）。因此"绕过系统"被列为**一等风险**（见 §4.4.6 绕过信号看板）。

## 4.6 本章"不这样做的替代方案及其代价"汇总

| 决策 | 选择 | 替代方案 | 代价 |
| --- | --- | --- | --- |
| 过滤位置 | 索引级下推 | 召回后裁剪 | 有效召回率跌至 20–30%，且性能差 3 倍以上 [B] |
| 桶粒度 | 粗桶优先，个人级例外 | 全细桶 | 存储放大 + 个人授权变成"人肉白名单"难审计 |
| 撤权路径 | overlay 优先 | 依赖索引刷新 | 20 秒越权窗口 [B] |
| 抽取触发 | 分级 + 预算熔断 | 每次会话都抽 | 成本不可控；官方亦指出 commit 开销需缓解 [A/B] |
| 冲突仲裁 | 阈值 + 双记并查 | 全自动 / 全人工 | 前者隐性仲裁、后者队列爆炸 |
| 归档 | 保留（只降层） | 到期删除 | 不可逆资产流失 |
| 阶段划分 | 硬退出点 + 可单域下线 | 一次性全量建设 | 治理/人力不足时全线烂尾；无退出点 ⇒ 无止损能力 |
| 度量优先级 | 正确性优先于性能 | 只看 QPS/延迟 | 性能全绿但过滤未下推 = 假绿（**最危险的"看起来没问题"**） |
| 记忆优先于知识 | 是（但可裁剪） | 知识优先 | 答案相关性下降；但**记忆错误代价高于知识缺失**，故保持记忆优先 |
| 治理工时预算 | 显式列入预算 | 不计（"顺带做"） | 治理是本方案最大的隐性成本，不计预算必被挤掉 |
