# macOS runtime source map

Which source files the macOS arm64 application actually needs, derived from the
build itself rather than from reading the tree. Written on 2026-09-22.

## How this was derived

The build records its own dependency graph. `scripts/host-production-activation.mjs`
and `scripts/electron-main-production-activation.mjs` bundle the two largest
runtimes from generated entry points and write the exact input list into
`dist/host-production-bindings.json` and `dist/electron-main-production-bindings.json`
under `executableGraph.inputs`. Both report `validated-clean-source`.

The remaining twelve runtimes are plain file entries, so their graphs were taken
from esbuild metafiles using the same options the build uses (`bundle: true`,
`external: ["electron"]`, `platform: "node"`, `target: "node22"`).

The provenance used here was generated by the last successful build. No file under
`source/` has been modified since, so the graph matches the committed tree.

## What is not source-built

Four runtimes in the composition are copied from the checksum-pinned 0.18.0
artifact rather than compiled from `source/`: the Electron shell
(`Contents/Frameworks/Electron Framework.framework`), `dist/deps`,
`dist/deps/node_modules`, `dist/native` and `dist/node-deps`. The renderer is also
an artifact in the default fidelity mode; only `rendererMode: "clean-source"`
builds it from `frontend/`.

`package-macos.mjs` refuses to run unless `process.platform === "darwin"`, so the
packaging path is macOS-only by construction.

## The 173 files outside every runtime graph

Being absent from a bundle is not the same as being dead. The 173 split into
three groups.

### Two type declarations

`source/mime-types.d.ts` and `source/shared/node/egress-tunnel/ws.d.ts` are
ambient declarations consumed by the typechecker, not by a bundle.

## Regenerating this map

Run a production build, then read the two provenance files and take the union of
their `executableGraph.inputs` entries that start with `source/`, then add the
esbuild metafile inputs for the twelve plain entry points listed above.

## Caution before deleting anything

Do not delete the 173 files on the strength of this document alone. Thirty-nine
of them are read by the manifests, tests, frontend build or scripts that
`npm run check` and `npm run publication:check` gate on. Any removal must be
followed by `npm run check`, `npm run frontend:build`, `npm run package` and
`npm run publication:check`, and the reconstruction manifests regenerated if
their inventories change.
