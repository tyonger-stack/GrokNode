# 应用窗口中文标题（2026-10-07）

截图中的 Chrome 页面中文正常，但应用列表显示乱码。真实 GET applications 也返回相同乱码，问题发生在 API 读取 X11 窗口标题时。

低权限命令使用 env -i 清理环境，未传递 UTF-8 locale。C locale 下，xprop 把 UTF8_STRING 输出为八进制字节转义；旧解析器把每个字节独立转成 Unicode 字符，生成 mojibake。对同一窗口 0x200004 的只读探测证实：未设置 locale 时输出字节转义；LC_ALL=C.UTF-8 时直接输出“百度一下，你就知道 - Google Chrome”。

修复在应用枚举命令中指定 LC_ALL=C.UTF-8，并在共享运行时的 Linux 命令中显式传递这个 locale。没有把 Mac 的整个环境传入 Linux。解析器按属性类型处理字节转义：UTF8_STRING 连续字节按 UTF-8 解码，旧式 STRING 保留 Latin-1 语义；原有 Unicode、引号和字面反斜杠保持正确。

新增三项回归覆盖真实中文转义、Emoji、字面转义、旧式 STRING 和应用枚举。修复前中文用例失败，修复后通过。全部 Node Agent API 回归 105 通过，0 失败；共享运行时和原 18770 真实网页均读取到正确标题。网页验证使用已有“全栈工程师”会话，点击刷新应用并选择 Chrome 窗口，没有发送模型任务或桌面输入。

原 API 状态已备份，确认没有运行中的回合后优雅重启 API，保留原端口、密钥、运行时目录和会话。没有修改或重启 GrokNode 程序及共享容器。用户在现有页面点击“刷新应用”即可重新获取标题；刷新整个页面后需重新输入访问密钥。
