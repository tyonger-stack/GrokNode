# 桌面重复接管修复（2026-10-07）

用户截图显示接管按钮返回 HTTP 409 desktop_busy。旧 API 对任何现有控制租约都拒绝新的接管票据，包括使用同一密钥的用户自己重复接管；切换观看时也未明确移交该密钥的控制。因此用户可能看着观看窗口但仍存在同密钥控制租约。

新增显式参数 replace_own_control（默认 false）。只有同一 credential 的活动租约可替换；签发票据时绑定旧租约 ID，新查看器真正打开时才撤销旧授权。不同密钥保持 409，即使调用者是 owner 也不自动抢占另一密钥。并发旧票据不能替换新建立的控制租约。

网页“接管”明确发送 replace_own_control:true，可重新建立自己的控制窗口；整桌面“观看”同样明确交还自己的控制。独立应用接管替换同密钥旧控制，但独立观看不撤销已有控制。发生其他使用者冲突时在桌面区显示中文提示，不再只在聊天头部放英文错误。

复现回归先红：同 credential 替换请求被原请求字段校验拒绝；修复后通过。覆盖旧 cookie 失效、view_only、其他密钥不可抢占与并发票据竞态。默认独占租约行为测试保持不变。全部 API 回归 101 通过，0 失败。

真实 Linux 桌面验收还发现 UI 竞态：重复接管未完成票据兑换就切换观看，旧控制 ID 的保护导致 iframe 收到 409。修复在查看器加载期间串行限制整桌面切换，并读取授权错误做中文提示。真实浏览器在原 GrokNode 测试 bot A 的 display 6 上连续“接管 → 再接管 → 观看 → 再接管”，每次查看器均为 noVNC_connected；最后手动交还，画面容器清空。没有执行桌面输入或模型任务。截图存在本机 .lab/desktop-replace.png。
