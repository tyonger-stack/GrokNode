## 详情页 hero 与账户行：用户报告的两处视觉差异（已修并在产物上复验）

用户反馈「我随便打开看就不一样」，附 Gmail 详情页截图：**logo 大得离谱**、**账户名显示成 `d...`**。
两个 app 同时在跑、同一份探针脚本量出来的对比（不是目测）：

| | 官方 0.66.0 | 修复前 | 修复后 |
| --- | --- | --- | --- |
| 详情区高度 | 734×**677** | 734×**1023** | 734×**675** |
| hero 区 | 734×**88** | 734×**421** | 734×**88** ✅ |
| hero icon | 56×56（img 55×55） | **401×401** | 56×56 ✅ |
| 账户块 | 734×**85** | 734×**100** | 734×**85** ✅ |

### 根因一：hero icon 的尺寸来自行内样式，不来自类

`DETAIL_TOOL_ICON_CLASSES` 的 13 个类在 0.18 与官方**逐条解析一致**，
而 `sand-tool-icon--logo` 在**两边样式表里都没有任何规则**。官方那个 span 的尺寸是**行内**给的：

```
span inline: width: 56px; height: 56px; border-radius: 16px
img  attrs : width="56" height="56"   （因自身 1px 边框计算成 55×55）
```

本地把尺寸设在了 `img` 上、span 什么都不设，于是 img 自己的 `width:100%`（`sand-h8yej3`）
对着一个无约束的 flex item 解析 → logo 撑成 **401×401**，详情区因此高了 346px。
注意 img 的属性官方是 **56/56** 不是 55 —— 本地原来写 55，是差 1px 的错。

### 根因二：hero 包装层与账户名列从来没挂上自己的类

hero 包装层本地是个**无类名的 `div`**。官方是
`sand-9f619 sand-78zum5 sand-dt5ytf sand-1v2ro7d`（flex 列 + gap 12px，56+20+12=88）。
四个声明在 0.18 **全都有**（box-sizing / display:flex / flex-direction:column / gap:12px），
所以**不需要 lift**，只是没挂上去 —— 结果 band 少了 12px，且 icon 少了可依附的列。

账户名同样：`DETAIL_ACCOUNT_NAME_CLASSES` 原本只有 2 个类，缺了
`display:flex` / `flex-direction:column` / `gap:1px`，名字和铅笔竖着堆（行 57 vs 官方 42）。
名字还用了带 `text-overflow:ellipsis` 的 `<dt>`，没有宽度可长就 21px 被截成 `d...`。
官方的正确结构是「1px-gap 的列 → 5px-gap 的行 → 名字 + 铅笔同行」。

### 守卫

`tests/marketplace-detail-hero-geometry.test.mjs`（3 条）。5 个变异全红，每个对应一个已发货的缺陷：
去掉 icon 行内尺寸、hero 包装层退回无类名 div、账户名退回带省略号的 `<dt>`、
账户名列删掉 `display:flex`、把 0.18 已有的类多余地 lift（不变量守卫）。

### 未解释的残留（不猜）

账户名内层盒子官方 **57×18**、本地 **57×15**，差 3px。已逐项排除：类名一致、`fontSize` 13px 一致、
`line-height` 都是 `normal`、`font-weight` 都是 420、字体族一致、letter/word-spacing 一致、
padding/margin/border 全为 0、无行内样式。**归因不了就不改** —— 外层账户行 42px、账户块 85px
两边**完全相同**，文字在同一基线位置，视觉上没有差别。

### 为什么这类缺陷能带着 894 个绿测试上线

节点上的**类名本来就是对的**，源码断言全部通过。缺的是两件「配方表达不了」的东西：
① 官方用**行内样式**定的尺寸，没有类可以承载；② **父容器/中间层从未被赋予自己的类**。
所以新增守卫断言的是行内样式与嵌套结构，不是「常量存在」。
